How Lifecycle works

Discover and Config's Sync both only ever observe — they set discovery_source/last_discovered on every push and never decide whether a device is stale. This page is the only thing that reads that data back out of NetBox, computes an age, and decides a staleness state. It's a deliberately separate concern.

Discovery states, by age of last_discovered

active — under {{ config.lifecycle_active_days }} days
Seen recently. Nothing to worry about.
stale — {{ config.lifecycle_active_days }}–{{ config.lifecycle_stale_days }} days
Hasn't been re-observed in a while. Native NetBox status is left alone here — going quiet for a bit shouldn't flip a device to offline prematurely.
review — {{ config.lifecycle_stale_days }}–{{ config.lifecycle_review_days }} days
Worth a human look. Still not touched at the NetBox status level.
decommission_candidate — {{ config.lifecycle_review_days }}–{{ config.lifecycle_decommission_days }} days
Long gone. NetBox's native status flips to offline here.
mia — over {{ config.lifecycle_decommission_days }} days
Very long gone. Also flips status to offline.
protected
Set this manually, directly in NetBox, to pull a device out of this reconciler entirely — it's skipped on every run, the same way Discover treats a human-locked managed asset. Use it for a device you know will go quiet on purpose (decommissioned-but-kept-for-records, seasonal gear, etc.) that you don't want auto-flagged.

Auto-heal

There's no special-case "recovery" logic needed — state is recomputed fresh from age on every run, with no memory of what it used to be. A device that gets rediscovered (bumping last_discovered) simply computes back to active the next time this runs, and if its status had been flipped to offline, that gets restored to active too. Confirmed working end-to-end: a device forced into mia healed cleanly back to active/active once it was freshly observed again.

Stored state vs. Computed now

Stored state is whatever's actually sitting in NetBox right now, from the last time the reconciler really ran. Computed now is this page doing the same math live, on every load, purely for display — it never writes anything. When they disagree, you'll see a pending update tag: that's exactly what would change the next time you click Run Lifecycle Reconciler Now or its cron fires.

What this never does

No deletion, ever, at any state — mia is a flag, not a countdown to removal. Decommissioning a device out of NetBox stays a human decision made directly in NetBox. This page's job stops at telling you what's gone quiet and for how long.

Run Lifecycle Reconciler Now

Runs lifecycle.py for real:

  1. Fetches every NetBox device with discovery_source=netdisco (i.e. everything Discover/Sync have ever pushed).
  2. Skips anything already protected.
  3. Sets first_discovered the first time it sees a device that doesn't have one yet.
  4. Computes age from last_discovered, maps it to a state, and writes discovery_state (and native status, only at the two ends of the scale) if it changed.
  5. Prints a summary, including a decommission-candidate list to review — never acts on it automatically.
