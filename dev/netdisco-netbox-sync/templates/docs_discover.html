How Discover works

This is Pipeline 2 — host discovery. It pulls end-host MAC/ARP data from Netdisco, stages it locally, classifies each asset, and lets you selectively promote the ones worth tracking to NetBox. It's separate from the infrastructure sync on the Config page, which pushes switches/firewalls directly with no staging step.

Classification states

unclassified
Seen, but not yet stable long enough to act on — needs {{ config.min_days_stable }} day(s) of continuous presence (MIN_DAYS_STABLE) before it graduates.
candidate
Stable enough for review on a lab or corporate VLAN (see the Config page's VLAN intent). These need a manual decision — Promote or Ignore — they're never auto-pushed.
managed
Actually pushed to NetBox. Automatic for infrastructure-intent VLANs once stable; manual (via Promote) for everything else. Once managed, the asset is human-locked — re-running Discovery only refreshes its last_discovered timestamp, it never gets reclassified or renamed out from under you.
ignore
Permanently excluded. Two flavors: auto-ignore (consumer OUI vendor, or an ignore-intent VLAN like the default VLAN 1) which can be re-evaluated later if the vendor blocklist changes, and human-ignore (you clicked Ignore) which is permanent.
promotion_failed
An infrastructure-VLAN asset tried to auto-promote and the push to NetBox errored. Retried automatically on the next Discovery run.
stale
Was managed, hasn't been re-observed in a while. (Deeper staleness tracking — with actual state transitions and NetBox status changes — lives on the Lifecycle page; this classification is the staging DB's own lighter-weight signal.)
archived
Was unclassified/candidate and went quiet for {{ config.prune_days }} day(s) (PRUNE_DAYS) without being re-observed. Nothing is deleted — the full record (first seen, VLAN, last switch/port) stays in the staging DB, just hidden from the default view. Hidden from the default view and the summary chips up top — use the Classification filter to see what's dropped off. If Netdisco sees the same MAC again, the next Discovery run automatically reclassifies it back to unclassified/candidate with its original first_seen intact — nothing further to do.

How an asset gets classified

Two inputs decide everything: which VLAN the asset is on (looked up against the Config page's VLAN policy) and how many days it's been continuously stable.

  1. Consumer device? Vendor OUI matched against the consumer blocklist → always ignore, regardless of VLAN.
  2. Gateway IP? Address ends in a configured gateway suffix (e.g. .1) → ignore, it's already a Device SVI elsewhere.
  3. VLAN intent = ignore → always ignore.
  4. VLAN intent = infrastructure → unclassified until stable, then auto-promotes to managed (needs a resolved IP; MAC-only stays ignored as a likely uplink/bridge).
  5. VLAN intent = lab or corporate → unclassified until stable, then becomes candidate for manual review.
  6. Unknown VLAN (not in Config at all) → same as lab/corporate: becomes a candidate once stable, not silently dropped.
Stability itself is just "still being seen." An asset re-observed by every Discovery run keeps its clock running; one that stops being seen sits still until it's pruned (see below) or, if it was already managed, until Lifecycle notices via its own thresholds.

What Promote actually does

Click the ⋯ menu on a candidate row. Every field is optional — leave it blank and it falls back to what's already staged:

  • Name → staged hostname (reverse-DNS from Netdisco, when available) → IP → MAC, in that order.
  • Role / Site → the VLAN's default_role/default_site from Config.

Behind the scenes it pushes a real Device to NetBox via Diode with: the resolved name/role/site, tenant and location from that VLAN's Config entry (if set), and two custom fields — discovery_source=netdisco and last_discovered=now — which is what feeds the Lifecycle page's staleness tracking. If Netdisco has a reverse-DNS name staged for the asset, it's also set as the IP address's dns_name in NetBox (same as the infrastructure sync on the Config page already does) — refreshed on every heartbeat, not just at promote time. The asset flips to managed and is locked from further reclassification.

Ignore / Unpromote

Ignore
Marks a candidate as permanently excluded. Stays in the staging DB for audit purposes, just never acted on again.
Unpromote
Resets a managed asset back to candidate in the staging DB only — it does not delete the device from NetBox. Use this when a device was removed from NetBox out-of-band and you want it to show up for review again instead of silently re-promoting on the next run.

Filters

  • Classification — show only the checked states.
  • Exclude — hide the checked states (handy for "everything except ignore").
  • VLAN — multi-select, show assets on any of the checked VLANs.
  • Vendor / search — vendor is exact-match from the OUI lookup; search matches MAC, IP, or hostname.

Switch/Port tracking

Every managed host's switch/port is tracked locally (staging DB only) and compared against the live Netdisco observation on every Discovery run. Unchanged → nothing happens, cheap no-op. Different → it's logged as a move, with the old and new location and when it happened.

This page only ever shows a small "N port changes need review" badge when there's something unacknowledged — the full, permanent audit log lives on its own Port moves page so it doesn't flood Discover once there are a lot of entries. Acknowledge just marks an entry reviewed (e.g. "yep, I moved that on purpose, documentation's updated") — it never deletes the row, so the log stays complete either way.

This is not pushed to NetBox as a real Cable object. Diode (the ingestion pipeline this tool uses) doesn't support creating Cable connections yet — confirmed directly against the real NetBox/Diode instance rather than assumed. Building that ourselves would mean hand-rolling the "find the existing cable, update it, don't create duplicates" logic Diode normally handles automatically for every other object type, which wasn't judged worth it just for this. What you get instead: an accurate, always-current record of where each device was last seen plugged in, and a clear audit trail of when that changed — without a stale or duplicated Cable object cluttering NetBox itself.

Run Discovery Now

Runs discover.py run for real, same as the CLI:

  1. Pulls MAC-table nodes from every infrastructure device Netdisco knows about, plus IP-inventory data for reverse-DNS/IP enrichment.
  2. Updates the staging DB and reclassifies everything against the current rules.yaml.
  3. Auto-promotes any newly-stable infrastructure-VLAN assets.
  4. Heartbeat: re-pushes last_discovered to NetBox for every already-managed asset, so Lifecycle staleness tracking stays accurate.
  5. Archives unclassified/candidate rows not re-observed in {{ config.prune_days }} day(s) (PRUNE_DAYS) — transient noise cleanup, nothing is deleted (see archived above). managed and ignore are never touched by this.
