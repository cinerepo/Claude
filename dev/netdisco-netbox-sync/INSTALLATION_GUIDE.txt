================================================================================
 netdisco-netbox-sync — Installation Guide
================================================================================

If you're installing this as part of observability-platform, you don't need
this file - playbooks/sync-tool.yml deploys it in-cluster instead (a
container image + a standing debug Deployment + two CronJobs, not the
venv/cron setup described below - see README.md for that). This guide is
for running the tool completely standalone (outside this repo's Ansible
automation, e.g. on a different host or site), where the venv+cron model
below is still a real, supported way to run it.

OVERVIEW
--------
Two pipelines in one package:

  sync.py       Infrastructure sync: SNMP-managed devices (switches, firewalls)
                → Netdisco → Diode → NetBox

  discover.py   Host discovery: end hosts from MAC/ARP tables
                → Netdisco → staging DB → manual review → Diode → NetBox


REQUIREMENTS
------------
  - Python 3.11 or higher
  - Network access to:
      Netdisco  (default port 5000)
      Diode     (default port 8080)
      NetBox    (default port 8000)
  - Diode and NetBox already deployed (Docker or bare metal)


INSTALLATION
------------

1. Copy the project directory to the target server:

     scp -r netdisco-netbox-sync/ user@server:/opt/netdisco-netbox-sync/
     # or clone from git if hosted there

2. Create and activate a Python virtual environment:

     cd /opt/netdisco-netbox-sync
     python3.11 -m venv .venv
     source .venv/bin/activate

3. Install dependencies:

     pip install -e .

4. Copy and configure the environment file:

     cp .env.example .env
     nano .env    # fill in your Netdisco URL, Diode credentials, etc.

5. Copy and configure site rules:

     cp rules.yaml.example rules.yaml
     nano rules.yaml    # define VLAN intents for this site

     (rules.yaml is the default RULES_FILE - point .env's RULES_FILE
     elsewhere if you want a different filename per site.)

6. Initialize the staging database:

     python discover.py status
     # This creates data/observed_assets.db automatically on first run.

7. Test connectivity:

     python sync.py
     # Should complete with "N ok / 0 errors" or similar.


RUNNING
-------

Infrastructure sync (run on a schedule):

     python sync.py

Host discovery (run on a schedule, then review):

     python discover.py run              # pull + classify
     python discover.py status           # summary
     python discover.py list-candidates  # review queue
     python discover.py promote 10.20.30.11 --name example-host-01 --role Server
     python discover.py ignore bc:24:11:f7:70:dd --reason "VM, tracked elsewhere"


CRON EXAMPLE (run as the deploy user)
--------------------------------------

     # Infrastructure sync every hour
     0 * * * * cd /opt/netdisco-netbox-sync && .venv/bin/python sync.py >> logs/sync.log 2>&1

     # Host discovery every 6 hours
     0 */6 * * * cd /opt/netdisco-netbox-sync && .venv/bin/python discover.py run >> logs/discover.log 2>&1

     Create the logs directory first: mkdir -p /opt/netdisco-netbox-sync/logs

     (The Ansible-driven install schedules both of these for you via
     config.yaml's netdisco_netbox_sync.sync_schedule/discover_schedule -
     no manual crontab editing needed on that path.)


MULTI-SITE DEPLOYMENT
---------------------
Each site gets its own .env and rules YAML. The code and virtualenv are shared.

     /opt/netdisco-netbox-sync/
     ├── .venv/                  (shared)
     ├── sync.py                 (shared)
     ├── discover.py             (shared)
     ├── sites/
     │   ├── site-a/
     │   │   ├── .env
     │   │   ├── rules.yaml
     │   │   └── data/           (site-specific staging DB)
     │   └── site-b/
     │       ├── .env
     │       ├── rules.yaml
     │       └── data/

     Run for a specific site:
       cd /opt/netdisco-netbox-sync
       set -a && source sites/site-b/.env && set +a
       python sync.py
       python discover.py run

     (The Ansible playbook in this repo targets a single site per
     config.yaml, matching the rest of the platform's single-deployment-
     per-config-file model - multi-site would mean running the install
     once per site with a different config.yaml each time, rather than
     the sites/ layout above.)


DECOMMISSION THRESHOLDS
-----------------------
Set in .env (can be different per site):

     STALE_DAYS=30        Managed device not seen in 30 days → flagged stale
     NOTIFY_DAYS=90       Not seen in 90 days → appears in list-stale output
     DECOMMISSION_DAYS=180  Not seen in 180 days → eligible for removal

Check stale devices:
     python discover.py list-stale


FILES
-----
  sync.py                Main infrastructure sync entry point
  discover.py            Host discovery CLI
  config.py              Loads .env into typed Config object
  models.py              Pydantic models for Netdisco API responses
  netdisco_client.py     HTTP client for Netdisco REST API
  transformer.py         Maps Netdisco data → Diode NetBox entities
  staging.py             SQLite staging table management
  classifier.py          Classification engine (VLAN intent + consumer OUI rules)
  rules.yaml.example     VLAN intent configuration template - copy to rules.yaml and edit per site
  consumer_oui_vendors.txt  Vendor strings to permanently ignore
  .env                   Live credentials (never commit to git)
  .env.example           Template — safe to commit
  data/observed_assets.db  SQLite staging DB (auto-created, never commit to git)

UPGRADING
---------
  cd /opt/netdisco-netbox-sync
  git pull           (if using git)
  source .venv/bin/activate
  pip install -e .   (picks up any new dependencies)
  # staging DB schema is additive — no migration needed for minor updates


TROUBLESHOOTING
---------------

"Failed to obtain access token: Unauthorized"
  → Check DIODE_CLIENT_ID and DIODE_CLIENT_SECRET in .env
  → Verify against the Diode deployment's own configured client credentials

"400 Bad Request" from Netdisco
  → Some report endpoints require Accept: application/json header (handled automatically)
  → Check NETDISCO_URL is correct and Netdisco is running

"Interface mode does not support untagged vlan"
  → Diode reconciler log message, not a script error
  → Means the interface was created without mode=access — fixed in current version

Staging DB is missing
  → Run `python discover.py status` to auto-create it
  → Ensure the data/ directory is writable
